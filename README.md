# тихо. — Django + React

Полноценная серверная версия тестового задания: Django 5.2 LTS, Django REST Framework, React 19, TypeScript, Vite. PostgreSQL в production; SQLite для локальной разработки.

**Статическое демо предыдущей версии:** https://middlewarer.github.io/TodoTesting/
Серверная версия разрабатывается в ветке `feat/django-react`; ссылка на её deployment будет добавлена после подключения хостинга. GitHub Pages не запускает Django.

## Возможности

- Добавление, выполнение и удаление задач; фильтры и удаление выполненных.
- Без входа — локальный список, совместимый с предыдущей версией.
- Регистрация и вход — отдельный личный список в базе данных.
- Изоляция задач по пользователю, серверная валидация, сессии и CSRF.
- 18 комбинаций оформления, сохранение настроек в браузере.
- Состояния загрузки и ошибок; повторные операции блокируются до ответа сервера.

Локальный и серверный списки разделены: вход не загружает старые задачи на сервер автоматически. При выходе снова виден локальный список. Очистка данных браузера удаляет только локальные задачи и оформление.

## Локальная разработка

Требуются Node.js 24 и Python 3.14.

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
npm ci
$env:DJANGO_DEBUG = 'true'
.venv\Scripts\python manage.py migrate
.venv\Scripts\python manage.py runserver
```

Во втором терминале: `npm run dev`. Открыть адрес, напечатанный Vite (с базовым путём `/static/`). Vite перенаправляет `/api/` в Django. Не открывать index.html напрямую.

Проверка собранной версии: `npm run build`, затем `python manage.py collectstatic --noinput` и `python manage.py runserver --nostatic`. Django отдаёт страницу, WhiteNoise — файлы сборки.

## Структура

- `src/App.tsx` — состояния приложения, гостевой и серверный режимы.
- `src/components/` — список задач, диалоги, настройки оформления.
- `src/api.ts` — HTTP-клиент, CSRF, ошибки ответов.
- `src/storage.ts` — совместимость локальных данных и предпочтений.
- `tasks/` — модель, сериализатор, API и проверки изоляции пользователей.
- `config/` — Django, настройки окружения и маршруты.
- `Dockerfile` — сборка React и запуск Django в одном сервисе.
- `.github/workflows/ci.yml` — проверки frontend и backend.

## Проверки

```powershell
npm test
npm run build
$env:DJANGO_DEBUG = 'true'
.venv\Scripts\python manage.py test
```

Проверяются совместимость старых данных, повреждённое хранилище, формы числительных, CRUD API, валидация, запрет доступа к чужим задачам, CSRF и вход/выход. Проверки браузерного интерфейса и deployment указываются отдельно по фактическим результатам.

## Публикация на Render

1. Создать аккаунт Render и подключить GitHub-репозиторий.
2. Создать PostgreSQL и сохранить Internal Database URL в секретной переменной `DATABASE_URL` web-сервиса.
3. Создать Docker Web Service из ветки `feat/django-react`. Файл `render.yaml` описывает бесплатный web-сервис; базу данных автоматически не создаёт.
4. Задать случайный `DJANGO_SECRET_KEY`; `DJANGO_DEBUG=false`. Домен Render подхватывается автоматически. Для собственного домена задать `DJANGO_ALLOWED_HOSTS` и при необходимости `CSRF_TRUSTED_ORIGINS`.
5. Дождаться сборки и успешного `/health/`, проверить регистрацию и личный список с двух аккаунтов.

Нельзя сохранять production SQLite на эфемерном диске. В production отсутствие DATABASE_URL или секретного ключа останавливает запуск. Миграции выполняются перед запуском Gunicorn; для нескольких одновременно разворачиваемых инстансов следует выделить отдельный release-job.

## Границы текущей версии

Нет восстановления пароля по почте, подтверждения email, общего доступа к спискам и автоматического импорта локальных задач. Ограничение частоты входа через DRF использует локальный кеш процесса: для публичного сервиса с нагрузкой нужен общий Redis и дополнительная защита на прокси. Резервное копирование PostgreSQL и мониторинг ошибок настраиваются на хостинге. Это проверяемое тестовое приложение, а не заявление о прохождении production-аудита.
